# 侧车（旁听服务）怎么搭

侧车是**独立的本地 Node 进程**，不是插件的一部分。它连 OneBot 的 WS，能看到所有消息，但**默认不发言**。

## 它解决什么

| 问题 | 侧车怎么解 |
| --- | --- |
| 记忆会忘、上下文会换 | 定时写「当前状态卡」，人设每回合读；轮换时写交接指针 |
| 「她」不该每句话都进模型 | 印象/好感/激素/数值全部本地算，0 token |
| 她太被动 | 定时判定：戳一戳、主动私聊、无聊去固定群冒泡 |
| 数值不自然 | 每分钟 tick 衰减/恢复，符合作息（0~8 点困、吃饭回饱食） |
| 说错话没人管 | 审计日志：谁触发了什么、有没有真的发出去 |

## 最小骨架

`侧车骨架.mjs`（本目录）就是可跑的起点，约 250 行：

```bash
# 先只算不发，观察两天
WS_URL=ws://127.0.0.1:3001 TOKEN=xxx BOT_QQ=1000000001 OWNER_QQ=1000000002 \
DATA_DIR=D:/my-bot/data MEM_DIR=D:/my-bot/memory node 侧车骨架.mjs

# 确认数值/状态卡正常后，再开真发
SEND=1 ...
```

它做了：

1. 连 WS，旁听 `post_type=message` 事件
2. 粗词表算好感（暖 +2 / 怼 −2 / 普通 +1）、激素、兴奋度
3. 每分钟 tick：激素半衰期、饱食/清洁/睡意/体力、兴奋度与淫荡/大胆漂移
4. 每 5 分钟落盘 + 写 `记忆/热记忆/当前状态.md`
5. 断线指数退避重连；`sendPrivate()` 只有 `SEND=1` 才发

## 建议往上加（按顺序）

1. **单实例锁**：pid 文件 + 命令行匹配，杀掉重复进程（最容易被坑）
2. **记忆三层**：热（状态卡+交接）/ 温（人物、约定、日记）/ 冷（台账）
3. **主动行为**：戳一戳（每天上限 + 最小间隔）、主动私聊（按时长分档由头）、固定群冒泡（无聊度阈值）
4. **场景判定**：侍寝/跑团/赛博精神病，各自状态文件 + TTL
5. **用量统计**：扫宿主会话日志算今天花了多少（本地算，0 token）
6. **审计**：所有「对外动作」写一行 JSON（时间、类型、目标、结果）

## 看护（Windows）

- 开机自启：计划任务「登录时运行」→ `cmd /c start /min 启动.cmd`
- 死了 5 分钟内拉起：看护脚本（VBS/PowerShell 循环）或计划任务重复触发
- 日志：`印象服务.log` 按天切；`tail` 看最近一行就知道活着没

## 坑

- **别用 `updatedAt` 当「上次接触时间」** → 每次写盘都刷新，2 小时归零永远不触发
- **别把「结果」当「条件」**（高潮度高 ≠ 在戏里）→ 数值只涨不落
- **保存时整体替换对象**会丢时间戳字段 → 合并而不是覆盖
- **两个侧车同时跑** → 数值双倍涨、消息双份发
