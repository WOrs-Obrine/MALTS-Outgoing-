# 侧车（旁听服务）怎么搭

侧车是**独立的本地 Node 进程**，不属于插件。它连 OneBot 的 WS，能看到所有消息，但**默认不发言**。

---

## 它解决什么

| 问题 | 侧车怎么解 |
|---|---|
| 记忆会忘、上下文会换 | 定时写「当前状态卡」，人设每回合读；轮换时写交接指针 |
| 不该每句话都进模型 | 印象 / 好感 / 数值 / 激素全部本地算，**0 token** |
| 她太被动 | 定时判定：戳一戳、主动打招呼、固定群冒泡 |
| 数值不自然 | 每分钟 tick 衰减/恢复，跟着作息走（夜里困、吃饭回饱腹） |
| 说错话没人知道 | 审计日志：谁触发、有没有真发出去、失败原因 |

---

## 最小骨架

本目录的 `侧车骨架.mjs` 是可跑的起点（约 230 行）：

```bash
# 先只算不发，观察两天
WS_URL=ws://127.0.0.1:3001 TOKEN=xxx BOT_QQ=1000000001 OWNER_QQ=1000000002 \
DATA_DIR=D:/my-bot/data MEM_DIR=D:/my-bot/memory node 侧车骨架.mjs

# 确认数值、状态卡都正常，再开真发
SEND=1 ...
```

它做了五件事：

1. 连 WS，只处理 `post_type=message` 事件
2. 粗词表算好感（暖 +2 / 怼 −2 / 普通 +1）、四条激素、情绪强度
3. 每分钟 tick：激素半衰期、饱足/清洁/睡意/体力、情绪强度回落
4. 每 5 分钟落盘 + 写 `记忆/热记忆/当前状态.md`
5. 断线指数退避重连；`sendPrivate()` 只有 `SEND=1` 才真发

## 往上加（按顺序，别跳）

1. **单实例锁**：pid 文件 + 命令行匹配，杀掉重复进程（最容易被坑）
2. **记忆三层**：热（状态卡 + 交接）/ 温（人物、约定、日记）/ 冷（工程台账）
3. **主动行为**：戳一戳（每日上限 + 最小间隔）、主动私聊（按时长分档选由头）、固定群冒泡（无聊度阈值）
4. **模式判定**：某些「模式」各自一个状态文件 + TTL，别混进主状态
5. **用量统计**：扫宿主会话日志算今天花了多少（本地算，0 token）
6. **审计**：每个「对外动作」写一行 JSON（时间、类型、目标、结果）

**为什么按这个顺序**：单实例锁最便宜、防的坑最狠；记忆和主动行为是「像人」的关键；统计和审计是「出问题能查」。
反过来做（先做统计审计再修锁）你会发现——数据全是错的，因为你根本不知道是哪个实例写的。

## 看护（Windows）

- 开机自启：计划任务「登录时运行」→ `cmd /c start /min 启动.cmd`
- 死了 5 分钟内拉起：看护脚本循环，或计划任务重复触发
- 日志：按天切；`tail` 看最后一行就知道活没活
- **查进程要按命令行匹配，别按映像名**：它可能是被桌面程序拉起的子进程

---

## 坑

- **别用 `updatedAt` 当「上次接触时间」** → 每次写盘都刷新，2 小时归零永远不触发
- **别把「结果」当「条件」** → 用「状态值高」当触发条件，会自锁（越高越算触发，永远不落）
- **保存时整体替换对象**会丢字段 → 深合并，不要覆盖
- **两个侧车同时跑** → 数值双倍涨、消息双份发
- **重启要有单实例保护**：先杀后起，否则看门狗会再补一个
