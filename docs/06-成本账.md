# 06 · 成本账：钱到底花在哪

这一份是我自己的账单复盘。数字来自真实账单 + 会话日志，不是估算。

---

## 1. 计价模型（先搞懂这个，别的才有意义）

按百万 token 计，三档价格：

| 项 | 含义 | 价格（空闲时） | 高峰时 |
|---|---|---|---|
| **命中缓存** input | 前缀和上一轮一致，直接复用 | 0.02 | 0.04 |
| **未命中** input | 新内容，模型从头读 | 1 | 2 |
| **输出** | 模型吐出来的字（含思考） | 4 | 8 |

**关键结论：同一段文字，放在「每轮都变的位置」比放在「稳定前缀」贵 50 倍。**
所有省钱手段，本质都是把东西往「稳定前缀」里挪，或者干脆不发。

---

## 2. 钱花在哪：三项几乎打平

取某一天的真实拆分（¥3.19 / 468 请求）：

| 项 | 用量 | 花费 | 占比 |
|---|---|---|---|
| 未命中 input | 1.16M | ¥1.16 | 36% |
| 命中 input | 53.7M | ¥1.07 | 34% |
| 输出 | 229K | ¥0.92 | 29% |

**这组数字说明三件事**：

1. 只压「未命中」最多省 36%——另外两项不动，你会很快碰到天花板；
2. **缓存命中不是免费的**：53.7M × 0.02 也是一块钱。上下文越长，命中也越贵；
3. 输出很贵（4 倍价）：话痨比话多更烧钱；「思考」也算输出。

## 3. 我的实测曲线

| 日期 | 花费 | 每请求未命中 token |
|---|---|---|
| 优化前 | ¥11.42 | 6396 |
| … | ¥8.37 | 5205 |
| … | ¥6.93 | 2578 |
| 优化后 | ¥2.57 ~ ¥3.15 | ~2500 |

一天 300~500 回合，折合 **每回合 ¥0.003~0.01**。

**「每请求未命中 token」是唯一值得盯的指标**：
它就是「你每轮重复付了多少钱」。这个数从 6396 掉到 2500，账单自然跟着掉。

---

## 4. 四个杠杆（按性价比排）

### 杠杆 1：人设分层（收益最大，代价最小）

- 做法：核心段进系统提示（一次），只留 1~2K 字的性格骨架每回合补
- 效果：每回合 14K 字 → 4K 字，账单直接砍半
- 代价：改核心段要新开会话才生效（改尾部即时生效）
- **这是第一件该做的事，没有之一。**

### 杠杆 2：轮换阈值别太勤

- 每换一次会话 = 一次冷启动（几万 token 未命中）
- 30 回合换 vs 50 回合换：冷启动次数差 60%
- 代价：上下文太长会稀释注意力、人设漂移
- 我的取值：50 回合 / 110K token / 24 小时兜底（模型窗口 128K，留 18K 余量）

### 杠杆 3：少说话，少思考

- 输出 ¥4~8/百万，是输入的 4~8 倍
- 语气规则里写「一句 3~15 字，最多三句」：不是限制人格，是省钱 + 更像人
- 思考强度：如果宿主支持调 `reasoningEffort`，闲聊场景降一档能省 20~30% 输出 token
- 代价：降太多会「变笨」，长链推理、代码、规划类任务会明显退化

### 杠杆 4：缓存友好

- 系统提示越稳定越好：别把「当前时间」「随机数」塞进系统提示
- 动态内容（时间、状态、聊天记录）放 user message 末尾——反正它们本来就要付费
- 反过来：把「每天都要变的东西」放系统提示，等于每轮都让它失效

---

## 5. 不要做的事

| 做法 | 为什么不行 |
|---|---|
| 把上下文砍到很小 | 她会失忆、重复问、人设崩；省下的钱不够你重开的火气 |
| 关掉思考 | 短回复可能看不出，长任务明显变蠢 |
| 装一堆「常驻提示」插件 | 每个都号称只要 150 token，一天三百回合就是 45K token |
| 只优化不测 | 你以为省了，其实只是把成本挪到了别处（比如输出变长） |

## 6. 怎么自己算

1. **从会话日志里抽 usage**：每条 assistant 消息通常带 `{input, cacheRead, output}` 三个数。
2. **去重**：按「(秒级时间, 三个数)」做 set，别按会话目录去重（同一个请求会出现在多个文件里）。
3. **对账**：连续三天和官方账单比，误差 >20% 说明你的口径错了。
4. **只看一个指标**：每请求未命中 token。它降了，钱就会降。

伪代码：

```
for each session file:
  for each assistant message with usage:
     key = round(time/1000) + '|' + input + '|' + cacheRead + '|' + output
     if key in seen: continue
     cost += input*1e-6*1 + cacheRead*1e-6*0.02 + output*1e-6*4
```

---

## 7. 一个月要多少钱

按一天 ¥3、一个月 30 天：**¥90**。
优化前是 ¥6.95/天 → **¥208/月**。

差的钱不算特别多，但差的**结构**很重要：
优化前是「每轮都在为同一段人设付全价」，优化后是「为真正的新内容付钱」。
前者会随着人设变长线性爆炸，后者不会。

---

## 8. 一句话总结

**每回合都发的东西，就是你的固定成本。**
把固定成本做成「一次注入 + 缓存命中」，把变动成本压到「只有对话」，这条路才走得长。
