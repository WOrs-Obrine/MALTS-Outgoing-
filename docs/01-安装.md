# 01 · 安装与启动

目标是先跑通最小闭环：**一条私聊，她回一句**。之后再往上叠功能。

## 前置

- Windows 10/11（本机常开，最好有断电重启自启）
- [DeepSeek Harness Desktop](https://github.com/)（下文简称 DSH Desktop）已装好，API key 可用
- 一个**小号 QQ**（别用主号，掉线/风控会烦）
- [NapCat](https://github.com/NapNeko/NapCatQQ) 或其他 OneBot v11 实现（负责登录 QQ、提供 HTTP/WS 接口）

## 1. NapCat 登录小号，开 WS

1. 装好 NapCat，用**小号**扫码登录
2. 打开「网络配置」，新建一个 **WebSocket 服务端**（正向 WS）
3. 记下端口（例如 `3001`）和 access token（自己设一个，后面插件填）
4. 验证：浏览器/工具连 `ws://127.0.0.1:3001` 能通

> NapCat 的 HTTP 服务不是必须的，插件走 WS 就够；但调试时 HTTP 调 `get_group_msg_history` 很方便。

## 2. 装 DSH Desktop 与插件

1. DSH Desktop 装好，能正常开一个会话、让它读写文件
2. 在 DSH 的插件市场上装 **`dsh-onebot-qq`**（本仓库文档以 `0.9.4` 为基准，更高版本 API 可能变）
3. 打开插件配置（`profiles/web/cordis.patch.yml`），填空题：

```yaml
onebot:
  wsUrl: ws://127.0.0.1:3001
  accessToken: "你的 token"
  botQQ: 1000000001          # 小号
  ownerQQ: 1000000002        # 你自己（大号）——主人权限只认这个号
  adminUsers: ["1000000002"] # 管理员
  dmPolicy: allowlist        # 私聊只回名单里的人
  dmFriendsOnly: true        # 私聊只回好友
```

4. 重启 DSH Desktop，日志里应出现 `bridge ready (N resumed chat(s))`
5. 私聊小号发一句话，应该能收到回复

**到这里就是最小可用版本了。** 后面每一步都是可选的增强。

## 3. 挂人设

1. 把人设 Markdown（见 `人设/`）放到你的提示词库目录，例如 `提示词库/我的鱼.md`
2. 在插件配置里把 persona 路径指过去
3. **人设是每回合现读的**：改完保存即生效，不用重启（这点很重要，调语气全靠它）
4. 验证：私聊里她自称/语气应变成人设里的样子

人设结构建议见 `docs/02-人设怎么写.md`。

## 4. 加旁听侧车（可选，但强烈建议）

侧车是一个**独立的本地 Node 进程**，通过 WS 旁听她的消息，**不占上下文、不花 token**，负责：

- 算印象/好感、激素、养成数值
- 定时写「当前状态卡」，供人设每回合读取
- 主动找人（戳一戳、私聊、固定群冒泡）
- 维护记忆文件、日记提醒、用量统计

做法（详见 `docs/03-功能清单.md` 的「侧车」一节，这里只给骨架）：

```
sidecar.mjs
  ├─ 连 ws://127.0.0.1:3001，订阅所有消息事件（旁听，不发言）
  ├─ 每收到一条消息 → 更新内存里的印象/激素/数值
  ├─ setInterval(tick, 60_000)  → 衰减、状态卡、主动行为判定
  └─ 需要她说话时，用 OneBot API 或插件注入一条「事件」给她
```

启动方式：`cmd` 一行拉起 + Windows 计划任务（开机自启、5 分钟看护重启），或 `watchdog.vbs`。
**务必保证单实例**（见 `docs/04-常见坑.md`）。

## 5. 加面板（可选）

一个本地 HTTP 服务/插件路由，浏览器里能看到并调：

- 养成数值、私密栏（按人切换）
- 激素四条 + 峰值线 + 最近事件
- 日记最近 7 天
- 用量（请求数、缓存命中、日均花费）
- 场景开关：侍寝、跑团、开发者模式、赛博精神病模式

把路由挂在 DSH Web 的同一个端口下最省事（注意要登录鉴权，返回 401 是正常的）。

## 6. 验证清单（每次改动后跑一遍）

- [ ] 日志有 `bridge ready`
- [ ] 私聊回一句
- [ ] 群里 @ 她回一句（不 @ 不回是设计）
- [ ] 工具数对得上（插件侧 `ctx.tools.register` 数量）
- [ ] 侧车只有一个进程
- [ ] 状态文件（开关）都是预期的开/关
- [ ] 看 `harness.log` 有没有 `agent create failed`
