# MALTS · 让一个 AI 在 QQ 里长期活着

这是一份**运行原理 + 搭建教程**，脱胎自我自己的 bot（一只鲸鱼娘）。

写它的目的只有一个：**授人以渔**。不是让你抄一份人设，而是让你看懂——

- 一个住在 QQ 里的 AI，由哪几块拼起来；
- 每一块为什么必须存在、彼此怎么咬合；
- 我在哪里踩过坑、坑的原因是什么、怎么绕开。

> **只讲原理和骨架**：不含我的私人语料、不当内容、QQ 号、群号和本机路径。
> 人设示例是干净的性格骨架，成人向内容请按你自己的需求写、自己存，本项目不提供。
> 请遵守平台规则与当地法律。

## 一、全景：四层，加一条硬规矩

```
QQ 客户端（你）
   │  收发
   ▼
NapCat（协议端，登录 bot 号）──WS──▶ dsh-onebot-qq（宿主插件）──▶ DSH Agent（大模型）
                                        │   ▲                        │
                                        │   │ 人设 Markdown（每回合现读）│ 工具调用
                                        │   └──────────────────────────┘
                                        ▼
                                 旁听侧车（本地 Node 进程，0 token）
                                        │
                                        ▼
                              状态文件（JSON / Markdown）
```

| 层 | 是什么 | 为什么要它 |
|---|---|---|
| **宿主** DeepSeek Harness Desktop | agent 运行时、工具系统（读写/终端/联网）、上下文轮换 | 模型不会「自己醒来」；宿主负责每次唤醒、给工具、裁上下文 |
| **通道** `dsh-onebot-qq` 插件 | 连 NapCat/OneBot，群聊/私聊路由，注册工具 | 模型不会发 QQ 消息；通道把「一条消息」翻译成一次 agent 回合，再把回复翻译成分段消息 |
| **人设** Markdown | 每回合现读的人格、语气、边界 | 改完即时生效，不用动代码；**人设是数据，不是提示词常量** |
| **旁听侧车** 本地 Node 进程 | 0 token 算印象、好感、激素、养成、动机；写状态、催主动消息 | 这些用模型算太贵太慢；本地算完只把「结论一行」塞进上下文 |

**那条硬规矩：只有「对话」花 token。** 旁听、算分、写状态、定时唤醒、刷空间、清理会话，全部在本地进程里做完。所以一天挂 24 小时，成本只和「聊了多少」有关，不和「在线多久」有关。

## 二、一次对话发生了什么（先有个印象）

1. 你在群里 @ 它 → NapCat 把消息推给插件。
2. 插件把这条消息**拼成一个大字符串**：最近聊天记录 + 安全边界 + 人设尾巴 + 当前状态（穿着、激素、身体、怒气……）+ 你的原话。
3. 宿主把「系统提示（含人设核心）+ 这段大字符串」发给模型。
4. 模型回话，可能顺手调工具（改数值、发图、发语音）。
5. 插件把回复分条发出去；旁听侧车同时收到一份，算印象/激素，写盘。
6. 每 10 分钟，侧车把养成数值往前推一点（饿、困、兴奋度回落……）。

细节在 [`docs/05-一次对话的生命周期.md`](docs/05-一次对话的生命周期.md)，那里标了代码位置。

## 三、快速开始（一个晚上能跑通第一句）

```text
1. 装 NapCat（Desktop 版最省事），登录小号，开正向 WS，记下端口/token
2. 装 DeepSeek Harness Desktop，配好模型 key
3. 装 dsh-onebot-qq 插件，填 botQQ / ownerQQ / wsUrl / token
4. 写人设 Markdown，放进「提示词库」目录，配置里指过去
5. 先跑通「私聊一句、她回一句」，再逐步加侧车 / 记忆 / 面板
6. 每一步都验证再往下加 —— 一次加三样，出问题你分不清是谁的锅
```

细节见 [`docs/01-安装.md`](docs/01-安装.md)。

## 六、丑话说在前

- **补丁会漂**：通道插件、面板、侧车、宿主四份代码互相依赖，宿主一升级就可能失效。我用「快照 + 哈希守护」兜底（见 03）。
- **人设越长越贵**：每回合都要发的东西，一个字都是钱。分层是必需品，不是优化项。
- **它不是「真活着」**：所谓「感觉」都是状态文件里的数字，靠注入让模型演出来。断线就是断线，别自我感动。
- **平台风险**：非官方协议端有被风控的可能。用小号，别拿主号试。
